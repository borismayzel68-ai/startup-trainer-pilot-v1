## 1. Цель и объём
**Цель:** закрыть D1–D5 и дать каждой роли кабинет, не меняя фреймворк и не ослабляя RBAC, Human Gate и шлюзы S6.
**Входит:** FR-001…FR-011. **Не входит:** FR-012 (заявка без приглашения), функции S4/S7, кабинеты покупателя и LSM.
**Предпосылки (подтверждено кодом, master 315e6c5):** Flask + gunicorn, Postgres 16, миграции 001–006, Google OAuth, `require_role` на каждом маршруте, 732 теста проходят (отчёт 30.10).

## 4. Технические решения
| ID | Решение | Альтернативы | Почему |
|---|---|---|---|
| TD-001 | Приглашения в таблице БД, env только для первого администратора | только env (как сейчас); готовая админка (Flask-Admin) | без перезапуска; минимальная правка `auth.py`; Flask-Admin — новая зависимость и свой вход, обходит `require_role` |
| TD-002 | Без собственных паролей; «смена пароля» = в Google | свои пароли | меньше ПДн и рисков; вход уже Google |
| TD-003 | Права — по всем ролям, экран — по активной роли | права только активной роли | не ломает 732 теста и ACCESS_MATRIX; Q-001 у Сергея |
| TD-004 | Оболочка — Jinja `base.html` без SPA-фреймворка | React/Vue | срок до 05.11; один стек |
| TD-005 | Админ = `owner` до 05.11 | отдельная роль `admin` | без миграции ролей; Q-002 у Бориса |
| TD-006 | `INVITE_CODE` остаётся только для машинных вызовов без сессии (если нужен), для сессии не проверяется | удалить совсем | обратная совместимость тестов; решить в T-001 по факту использования |

**Требуют согласования:** TD-003 (Сергей), TD-005 (Борис).
