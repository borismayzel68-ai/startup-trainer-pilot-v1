## 1. Цель и объём реализации

**Цель:** «Начать» создаёт сессию или честно объясняет, почему нет; поле «Код доступа» оформлено по решению Бориса.

**Входит:** диагностика; клиентская обработка ответа (индикатор, блокировка, ошибки); тексты ошибок; тесты; удаление поля «Код доступа» (решение Q-B2 от 31.10).

**Не входит:** вопросы тренажёра, ИИ-логика, отчёты, вход, роли.

**Исходные требования:** FR-001…FR-006, NFR-001…005, AC-001…008.

**Предпосылки:** вход работает под `founder` со scope или `owner`.

## 2. Текущее состояние системы (As-Is)

- **Подсистемы:** страница анкеты (`templates/index.html`), эндпоинт `POST /api/start` (`app.py:553-651`), хранилище сессий `SESSIONS` (`app.py:72-75`), RBAC (`auth.py`), ИИ-клиент (`app.py:34-35`).
- **Кнопка:** `<button onclick="startSession()">Начать</button>` и `<p id="startErr" class="error">` (`index.html:74-75`).
- **`startSession()`:** собирает `FormData`, `fetch('/api/start',{method:'POST',body:fd})`, затем `await r.json()`; при `!r.ok` пишет `j.error||'Ошибка'` в `startErr`; **нет `try/catch`, нет индикатора, нет блокировки кнопки** (`index.html:96-121`). Если ответ не JSON или сеть упала — исключение, сообщения нет (следствие кода; сам сбой на стенде НЕ ПОДТВЕРЖДЁН).
- **CSRF:** обёртка `window.fetch` добавляет `X-CSRF-Token` для не-GET (`index.html:24-28`).
- **Проверка на сервере, по порядку:** `require_role(["founder","owner"], scope=project_id)` (`app.py:553-554`) → `invite_code == INVITE_CODE` (`app.py:556-557`) → `consent == "true"` (`558-559`) → обязательные поля (`561-592`) → PDF (`594-600`) → маршрутизация (`602`) → запись `SESSIONS[sid]=s` (`646`) → `next_question(s)` (вызов ИИ, `647`) → запись ещё раз (`648`) → `trainer_sessions` в cookie (`649-650`) → JSON (`651`).
- **Код доступа:** поле `id="code"`, подсказка «Код пилота» (`index.html:62`); настройка `INVITE_CODE`, значение по умолчанию задано прямо в коде (`app.py:65`); для staging — проверка «текст комментария вместо значения» (`staging_guard.py:41`); в `.env.example` есть имя настройки; отмечено в `docs/reports/STAND_CHECK_2026-10-30.md:36,45` (слабый дефолт, низкий риск) и в чек-листе `docs/for-sergey/02_TZ_chek-list_priyomki_stenda.md:58`.
- **Лимиты:** запрос ≤ 20 МБ (`app.py:82`); gunicorn без `--timeout` ждёт 30 с по умолчанию (`docs/for-sergey/03…md:105`, рекомендация, не проверено).
- **Сообщения/журнал:** на 401/403 пишется `audit_log` (`auth.py:154-158`); на успешный `POST` — запись `change allow` с кейсом (`auth.py:179`).
- **Ссылки на код:** `templates/index.html`, `app.py`, `auth.py`, `routing_v2.py`, `question_engine_v2.py`, `tests/`.
- **Неизвестно (исследовать):** какая именно ошибка срабатывает на стенде (НЕ ПОДТВЕРЖДЕНО); как настроен прокси и таймаут; роль и scope тестового пользователя; есть ли автотесты `/api/start` (НЕ ПОДТВЕРЖДЕНО, не искал по `tests/`).

## 8. Стратегия реализации и зависимости

### Порядок поиска причины «Начать не сохраняет / форма молчит» (T-301)
Идти сверху вниз, записывая результат каждого шага:
1. **Браузер:** открыть консоль и вкладку «Сеть», нажать «Начать». Ушёл ли `POST /api/start`? Какой статус и тип тела (JSON/HTML)?
   - Запроса нет → ошибка JS до `fetch` (консоль) или поле `deck`/форма (`index.html:96-117`).
   - 401/403/400 JSON, но текста нет → смотреть `startErr` (`index.html:75`).
   - Статус 413/500/502/504 и тело HTML → клиент падает на `r.json()` (`index.html:118`) — «молчит».
2. **Журнал доступа:** `GET /admin/audit` (под `owner`): запись `change` по `/api/start` — `allow` (с `case=…`) или `deny` с `detail`: `unauthenticated`, `forbidden`, `csrf` (`auth.py:154-158,176,179`).
   - `csrf` → токена нет (кэш страницы без `<meta csrf-token>`, или сессия истекла).
   - `forbidden` → роль не `founder/owner` либо scope не совпал с `project_id` (поле по умолчанию `VC-178`, `index.html:37`).
3. **Ответы приложения:** `invite_code_invalid` (код не совпал с `INVITE_CODE`), `consent_required` (галочка), `*_required` (поле).
4. **Логи приложения и прокси:** есть ли 500 с трассировкой в `next_question` → `call_json` (ИИ: ключ/URL/модель не заданы); 504/502 от прокси (таймаут); 413 (размер).
5. **Хранилище:** создалась ли запись сессии (`GET /api/session/<id>` под `owner`, либо запись в таблице сессий по времени). Запись есть, а экран «молчит» → ошибка после `SESSIONS[sid]=s` (вероятно ИИ, `app.py:646-647`).
6. **Результат:** «причина: …, подтверждено …» или «не установлена; исключено: …».
