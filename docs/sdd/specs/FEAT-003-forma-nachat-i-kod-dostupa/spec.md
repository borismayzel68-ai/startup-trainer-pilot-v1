## 1. Цель и контекст

### 1.1 Проблема
По итогам звонка 31.10 на стенде: (1) кнопка «Начать» в анкете «ничего не сохраняет»; (2) форма не отправляется и молчит — ни ошибки, ни результата; (3) поле «Код доступа» стоит без пояснения. Причина (1)–(2) в репозитории **НЕ ПОДТВЕРЖДЕНА**: ниже — что известно по коду и порядок поиска. **РЕШЕНО Борисом 31.10.2026 (Q-B2): поле «Код доступа» убрать.** Основание: это не защита — значение угадывается из кода (ЗАЯВЛЕНИЕ ИСТОЧНИКА: Сергей узнал его через ИИ из кода; ФАКТ: значение по умолчанию лежит в репозитории, `app.py:65`). Доступ определяется входом через Google и списком допущенных пользователей, который администратор ведёт без пересборки (FEAT-001 FR-010, FEAT-004 FR-007). Вариант «оставить с пояснением» отклонён 31.10.

### 1.2 Ожидаемый результат
Нажатие «Начать» либо создаёт сессию тренажёра и показывает первый вопрос, либо показывает понятную причину отказа на русском. Метрика: 0 «молчаливых» сбоев — в каждом тестовом сценарии ошибки (AC-002…AC-005) человек видит сообщение; успешный сценарий создаёт запись сессии.

### 1.3 Область действия
**Входит:** кнопка «Начать»; сохранение сессии; сообщения об ошибках; поле «Код доступа» (вариант А или Б); порядок поиска причины по коду и журналу.  
**Не входит:** вход (FEAT-001), кабинеты (FEAT-002), вопросы тренажёра и ИИ-разбор, отчёт; смена правил оценки; текст согласия.

## 3. Функциональные требования

### FR-001 — «Начать» создаёт и сохраняет сессию
- **Приоритет:** Must
- **Описание:** При корректных данных Система ДОЛЖНА создать сессию (`POST /api/start`), сохранить её и показать первый вопрос.
- **Условия:** вошёл `founder`/`owner`, поля заполнены, галочка согласия отмечена.
- **Входные данные:** поля формы (ФАКТ `index.html:96-117`): `invite_code`, `project_id`, `project_name`, `founder_name`, `founder_email`, `jurisdiction`, `target_markets`, `intended_use`, `product_class`, `stage`, `user`, `buyer`, `payer`, `mode` (A/B/C), `hypothesis_a`, `hypothesis_b`, `description`, `consent`, `deck` (PDF).
- **Результат:** JSON сессии с `id` и `current_question` (ФАКТ `app.py:646-651`).
- **Бизнес-правила:** обязательны `project_id` (формат VC-ID), `project_name`, `founder_name`, `founder_email`, `jurisdiction`, `intended_use`, `product_class`, `mode`; для `MULTI` — минимум 2 рынка; PDF — только `application/pdf` (ФАКТ `app.py:561-600`). Правила **не менять**.
- **Ошибки и исключения:** см. FR-003.
- **Связанные критерии приёмки:** AC-001

### FR-002 — Результат нажатия всегда виден
- **Приоритет:** Must
- **Описание:** После нажатия «Начать» Система ДОЛЖНА показать индикатор «Отправляем…», заблокировать повторное нажатие до ответа и в любом исходе (успех, ошибка JSON, ответ не JSON, сбой сети, таймаут) показать сообщение.
- **Бизнес-правила:** сейчас `startSession()` без `try/catch`: если ответ не JSON или сеть упала, `r.json()`/`fetch` выбрасывает ошибку, сообщение не показывается, форма «молчит» (ФАКТ `index.html:118-120`; поле ошибок `index.html:75`).
- **Связанные критерии приёмки:** AC-002, AC-003

### FR-003 — Понятные сообщения об ошибках
- **Приоритет:** Must
- **Описание:** Система ДОЛЖНА показывать причину на русском и что делать, для каждой группы ошибок.
- **Бизнес-правила (ФАКТ — какие ответы даёт сервер):**

| Ситуация | Ответ | Источник |
|---|---|---|
| Нет входа | 401 `unauthenticated` | `auth.py:187-188` |
| Нет роли/кейса | 403 `forbidden` «Доступ запрещён» | `auth.py:189` |
| Нет CSRF-токена | 403 `csrf` | `auth.py:175-176` |
| Неверный код доступа | 403 `invite_code_invalid` «Неверный код доступа» | `app.py:556-557` |
| Нет галочки согласия | 400 `consent_required` | `app.py:558-559` |
| Нет/неверное поле | 400 `*_required`, `*_invalid` | `app.py:561-592` |
| Не PDF | 400 `deck_mime_invalid` | `app.py:598-599` |
| Слишком большой запрос (>20 МБ) | 413, тело — **не JSON** (поведение Flask; НЕ ПОДТВЕРЖДЕНО) | `app.py:82` |
| Ошибка ИИ/сервера | 500/502/504, тело вероятно **не JSON** (НЕ ПОДТВЕРЖДЕНО) | `app.py:647`; `docs/for-sergey/03…md:105` (таймаут 30 с) |

- Тексты ПРЕДЛОЖЕНО, утверждает Борис. Сырые коды и трассировки человеку не показывать. Коды и статусы сервера **не менять**.
- **Связанные критерии приёмки:** AC-002, AC-003, AC-004, AC-005

### FR-004 — Порядок поиска причины «не сохраняет / молчит»
- **Приоритет:** Must
- **Описание:** Должен существовать воспроизводимый порядок (`plan.md`, раздел 8) и записанный результат: причина или «не установлена» с перечнем исключённого.
- **Связанные критерии приёмки:** AC-006

### FR-005 — Убрать поле «Код доступа» (решение Q-B2 от 31.10)
- **Приоритет:** Must
- **Описание:** РЕШЕНО Борисом 31.10: Система ДОЛЖНА убрать поле «Код доступа» из анкеты и не требовать `invite_code` в `POST /api/start`. Защита остаётся: вход Google + список допущенных + роль + scope. Изменение проверки в `app.py` — защищённый путь, **высокий риск**.
- **Бизнес-правила (ФАКТ):** по умолчанию `INVITE_CODE` имеет публичное значение в коде (`app.py:65`; отчёт `docs/reports/STAND_CHECK_2026-10-30.md:36,45`: слабый дефолт отмечен как низкий риск). Код доступа защитой не является; убирая проверку, не терять реальную защиту: роль и scope остаются, и перед удалением тест подтверждает, что без входа и без нужной роли `POST /api/start` по-прежнему отказывает.
- **Связанные критерии приёмки:** AC-007

### FR-006 — Вариант «оставить с пояснением» — ОТКЛОНЕНО 31.10
- **Приоритет:** не применяется
- **Описание:** Неприменимо, потому что Борис 31.10.2026 решил поле убрать (Q-B2): код доступа не защита.
- **Связанные критерии приёмки:** AC-008 (отклонён)

## 4. Сценарии использования

### UC-001 — Основатель запускает анкету
**Актор:** основатель. **Предусловия:** вошёл, scope = его `project_id`.  
**Основной поток:** 1) заполняет анкету; 2) отмечает согласие; 3) нажимает «Начать»; 4) видит «Отправляем…»; 5) получает первый вопрос.  
**Альтернативные потоки:** A1: прикладывает PDF → текст извлекается (ФАКТ `app.py:594-600`).  
**Ошибочные потоки:** E1: не отмечено согласие → «Нужно согласие…» (400); E2: чужой `project_id` → 403 «Доступ запрещён», сообщение с объяснением; E3: неверный код → сообщение (вариант А — нет такого случая); E4: ответ не JSON/сбой сети → «Не удалось отправить, попробуйте ещё раз»; E5: PDF не PDF → «Разрешён только PDF».  
**Постусловия:** сессия сохранена (успех) либо ничего не создано, форма заполнена прежними значениями.

### UC-002 — Роль без права
**Актор:** `investor`. Нажимает «Начать» → 403 → сообщение «У вашей роли нет доступа к анкете» (ПРЕДЛОЖЕНО).

## 9. Граничные случаи и обработка ошибок

- **Пустые/некорректные значения:** `project_id` не VC-формата → 400; `MULTI` с одним рынком → 400; текст >лимитов обрезается (ФАКТ `app.py:607-629`).
- **Повторные запросы:** двойное нажатие создаёт две сессии (НЕ ПОДТВЕРЖДЕНО защитой от дублей) → блокировка кнопки (FR-002).
- **Тайм-ауты:** ответ ИИ долгий; сервер с 30 с таймаутом может оборвать (ФАКТ `docs/for-sergey/03…md:105`, рекомендация, НЕ ПОДТВЕРЖДЕНО на стенде).
- **Частичный успех:** сессия записана до вызова ИИ (`app.py:646-647`), ИИ упал → «висящая» сессия; поведение — решение Борису/MOS Tech (TBD).
- **Файл:** не PDF → 400; >20 МБ → 413 (ФАКТ `app.py:82`).
- **Доступ к чужим данным:** чужой кейс → 403 и запись в журнал (ФАКТ `auth.py:154-158`).
