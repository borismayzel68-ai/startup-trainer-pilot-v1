## 1. Цель и объём реализации

**Цель:** вход через Google работает на стенде, отказы понятны, есть «Выйти», порядок ролей и тексты согласия определены без выдуманных правил.

**Входит в объём:** диагностика #114; сообщения об отказах; кнопка «Выйти»; тесты входа; механизм текстов согласия (после решения юриста); порядок «кто вы» (после Q-B6).

**Не входит в объём:** кабинеты (FEAT-002), форма (FEAT-003), админ-панель (FEAT-004); новый способ входа; перепись `auth.py`.

**Исходные требования:** FR-001…FR-009, NFR-001…NFR-005, AC-001…AC-010.

**Предпосылки:** `auth.py`, `auth_store.py`, `pdn_consent/` уже в репозитории; стенд на HTTPS.

## 2. Текущее состояние системы (As-Is)

Только подтверждённые факты (прочитан код).

- **Затрагиваемые подсистемы:** вход и RBAC (`auth.py`, `auth_store.py`), страница согласия (`pdn_consent/blueprint.py`, `templates/consent.html`), замок стенда (`staging_guard.py`).
- **Точки входа:**
  - `GET /auth/login` — без согласия редирект `/consent`; без настроек Google — 503 `oauth_not_configured`; иначе редирект в Google со `state`/`nonce`, `prompt=select_account` (`auth.py:226-240`).
  - `GET /auth/callback` — проверки `state`, обмен кода, `iss/aud/exp/nonce/email_verified`, список допущенных, согласие, совпадение почты, создание пользователя и грантов, новая сессия, редирект `/` (`auth.py:243-283`).
  - `POST /auth/logout` (`auth.py:286-291`); `GET /auth/me` (`auth.py:294-299`).
  - `GET/POST /consent`, `POST /consent/revoke` (`pdn_consent/blueprint.py:106-154`).
- **Список допущенных:** `AUTH_ALLOWLIST` (`auth.py:35-52`); на staging обязателен, не пуст, основатель без кейса запрещён (`staging_guard.py:13,57-72,76-83`).
- **Адрес возврата:** `AUTH_REDIRECT_URI` или `<корень запроса>/auth/callback` (`auth.py:73-74`).
- **Cookie:** Secure, HttpOnly, SameSite=Lax, 12 ч (`app.py:64`); на staging — `SESSION_SECRET` ≥ 32 символов (`staging_guard.py:25,63-64`).
- **Кнопка «Выйти»:** в `templates/` отсутствует (поиск «logout»/«Выйти» по `templates/`, `app.py` — нет совпадений).
- **Сообщения отказа:** JSON-коды, страниц нет (`auth.py:250,256,263,267,271,274`). Исключение: отказ 401 для HTML-GET — редирект на `/auth/login` (`auth.py:156-157`).
- **Согласие:** один текст `text_v0-draft.txt` (`blueprint.py:20,38-40`); потоки `s1_intake`, `investor_login` (`blueprint.py:23`); подсказка о совпадении почты (`consent.html:43`).

## 3. Целевая архитектура (To-Be)

**Общая схема (текстовая):** `Посетитель → /consent (согласие) → /auth/login → Google → /auth/callback → проверки → сессия → /`. Отказ на любом шаге → страница с понятным текстом + запись в журнал. «Выйти» → `POST /auth/logout` → `/consent`.

| Компонент | Ответственность | Изменение | Взаимодействия |
|---|---|---|---|
| `auth.py` (login/callback) | проверки входа | Без изменений логики; ПРЕДЛОЖЕНО: для браузера отдавать страницу отказа | Google, журнал |
| Страница отказа (шаблон) | текст и следующий шаг | Новый | `auth.py` |
| Кнопка «Выйти» (общий фрагмент шапки) | вызов logout с CSRF | Новый (общая шапка — FEAT-002) | `/auth/logout` |
| `pdn_consent` | согласие | Без изменений (тексты по ролям — после юриста) | `auth.py` |
| `staging_guard.py` | замок стенда | Без изменений | — |

**Поток данных:** см. spec UC-001. Проверки callback идут в фиксированном порядке (`auth.py:246-283`); порядок сохранить.

**Границы и принципы:** контракты не менять; страница отказа — надстройка над теми же кодами и статусами.

## 8. Стратегия реализации и зависимости

**Порядок поиска причины #114 (T-101):** по журналу `GET /admin/audit` и настройкам (только названия):
1. `GET /health` отвечает? Приложение запущено на HTTPS, а не на HTTP (Secure-cookie).
2. `GET /auth/login` без согласия → редирект на `/consent`? С согласием → редирект в Google или 503 `oauth_not_configured` (тогда не заданы `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`)?
3. В Google возвращается ошибка redirect_uri? Сравнить `AUTH_REDIRECT_URI` с адресом, зарегистрированным в консоли Google (`…/auth/callback`).
4. Запись журнала `login deny` с `detail`: `oauth_state_or_error` (потеряна cookie/state → HTTP или домен), `token_exchange_failed` (секрет клиента неверен/недоступна сеть), `id_token_invalid` (не тот client id, `email_verified`), `not_in_allowlist`, `pdn_consent_revoked`, `pdn_consent_email_mismatch` (`auth.py:249,255,262,266,270,273`).
5. В логах приложения — «OAuth: обмен кода не удался» (`auth.py:254`).
6. Если секрет клиента неверен/утёк — Q-B3 (перевыпуск решает Борис; значение секрета не писать нигде).

Результат: одна строка «причина: …, подтверждено записью журнала от <время>».

**Этапы:**
1. T-101, T-102 (диагностика и проверка настроек).
2. T-103, T-104 (выход, сообщения), T-105 (тесты) — не зависят от Q-B3.
3. T-106, T-107 — после Q-B6 и Q-B4.

**Параллелизация:** T-103 и T-104 независимы (разные файлы).

**Ограничения:** `app.py` — защищённый путь (высокий риск); ядро Flask не переписывать до 06.11.
