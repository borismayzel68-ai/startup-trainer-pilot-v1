## 1. Цель и объём реализации

**Цель:** панель доступна назначенным, ПДн маскированы, просмотры записаны, реальных данных нет.

**Входит:** проверка доступа тестами; журнал с идентификаторами; маскирование (после Q-B7); проверка синтетики (после Q-B5).

**Не входит:** новая админ-функциональность; юридическая оценка; уведомление РКН; вход.

**Исходные требования:** FR-001…FR-006, NFR-001…005, AC-001…006.

**Предпосылки:** вход и роли работают (FEAT-001/002).

## 2. Текущее состояние системы (As-Is)

- **Подсистемы:** админ-маршруты в `app.py`; журнал в `auth_store.py`; замок и проверка синтетики в `staging_guard.py`.
- **Маршруты панели:**
  - `GET /admin/sessions` — `@require_role(["owner"], scope="*")`; возвращает `<pre>` с JSON `list(SESSIONS.values())` целиком, с экранированием `&` и `<` (`app.py:730-734`). Без маскирования, фильтра полей, пагинации.
  - `GET /admin/audit` — `owner`, `*`; `limit` 1…500 (по умолчанию 200); нечисловой → 400 `bad_limit` (`app.py:736-743`).
  - Старый `/admin?key=` удалён, 404 (`docs/ACCESS_MATRIX.md:47`).
- **Что лежит в сессии:** `founder_name`, `founder_email`, `description`, `deck_text` (до 30 000 символов), `qa` (ответы), `feedback`, `report` и др. (`app.py:604-644,117-128,719-728`). Публичный вид скрывает `deck_text`, `idempotency_key`, `event_*` (`app.py:110-115`), админский — нет.
- **Журнал:** запись на каждый разрешённый и отказанный запрос: время, actor, action (`view`/`change`), object (путь), result, IP, detail (кейс, роли) (`auth.py:154-158,179`; `auth_store.py:30-32,117-120`). Какие записи просмотрены — не пишется. Сами данные кейсов в журнал не попадают (`ACCESS_MATRIX.md:65`).
- **IP:** `request.remote_addr`; за доверенным прокси его подменяет `ProxyFix` при `TRUSTED_PROXY_COUNT` (`auth.py:82-85`, `app.py:57-62`). `ACCESS_MATRIX.md:63,70` описывает иначе (`X-Forwarded-For` как есть) — расхождение документа с кодом.
- **Синтетика:** `STAGING_SYNTHETIC_ONLY` (по умолчанию true; иное — отказ старта) (`staging_guard.py:86-89,136-139`); `check_synthetic_data` смотрит `users` без `is_synthetic`, исключая почты из списка допущенных; только Postgres; недоступная БД = отказ (`staging_guard.py:92-114`); включается только при `APP_ENV=staging` (`staging_guard.py:133-134`). В `users` колонка `is_synthetic` есть (`auth_store.py:22-23`). Проверки таблицы сессий в файле **нет** (НЕ ПОДТВЕРЖДЕНО нигде в других файлах — не искал).
- **Правило проекта:** `CLAUDE.md` — «только синтетика до уведомления РКН»; отчёт о проверке стенда 30.10: `docs/reports/STAND_CHECK_2026-10-30.md` (в нём отмечены проверки защиты; детали по панели не сверялись).
- **Технический долг:** `/admin/sessions` отдаёт всё; нет пагинации; сессии хранятся 30 дней по умолчанию (`SESSION_RETENTION_DAYS`, `app.py:66`).
- **Ссылки на код:** `app.py`, `auth.py`, `auth_store.py`, `staging_guard.py`, `tests/test_auth.py`, `tests/test_mos6_staging.py`.
- **Неизвестно (исследовать):** что именно показывает панель Сергея (ЗАЯВЛЕНИЕ ИСТОЧНИКА, Q-001); откуда реальные данные (Q-002); есть ли тесты на `/admin/*` (НЕ ПОДТВЕРЖДЕНО).
