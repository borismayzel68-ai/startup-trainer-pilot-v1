## 5. Риски

1. Перенос задевает защищённые пути `REVIEW.md` §3: `app.py`, миграции, `Dockerfile`, при ORM ещё `scripts/hq018_migrate.py`. Такой PR — высокий риск, мерж Бориса. Этот документ пути не трогает.
2. Контракты адресов (`/auth/login`, `/auth/callback`, `/api/start` и остальные) `AGENTS.md` запрещает менять без отдельного решения. Перенос имеет смысл только при тех же адресах. Это уже заложено в дни, и это же главный способ сорвать срок: «заодно поправим URL».
3. Заголовок CSRF сейчас `X-CSRF-Token` (`auth.py:135`, скрипт в `index.html`). Страница тренажёра перестанет отправлять ответы, если при переносе заголовок сменится. Совпадает ли имя с заголовком Django по умолчанию, здесь не проверялось: Django в репозиторий не установлен.
4. Два диалекта SQL (SQLite в тестах, Postgres на стенде) сидят в `session_store.py` и `s1_intake/store.py`. Переход на ORM легко чинит Postgres и ломает локальные тесты, или наоборот.
5. Отчёт `docs/reports/STAND_CHECK_2026-10-30.md` записал «SQL-инъекций нет» на проверке 30.10. Этот вывод здесь не перепроверялся. ORM не закрывает дефекты пути D2–D4 (приглашение только через перезапуск, инвестор видит анкету стартапа, нет кабинета и «Выйти») — они описаны в `docs/reports/STAND_REVIEW_2026-10-31.md` и закрываются T-002…T-006, а не сменой каркаса.
6. Дата входа участников на стенд не назначена (`docs/STATE.md`, перенос 31.10). Звонки-интервью 04–06.11 идут на вымышленном примере и стенд не требуют. Задержка переноса бьёт по будущему входу на стенд, не по этим звонкам.
7. Q-B9 (брать ли за основу каркас админки, показанный Сергеем) открыт. Кода того каркаса в этом репозитории нет, дни на него не считались.
8. Открытый PR #125 меняет `app.py` и `templates/index.html`. Оценка снята с `master` без этого PR. Слитый #125 добавит к переносу ещё один набор правок Flask.

## 7. Рекомендация (ПРЕДЛОЖЕНО, не решение)

Остаться на Flask и делать T-002…T-006. Полный переход на Django не начинать, пока не будет прохода четырёх ролей (T-007) и отдельной записи Бориса, которая снимет Q-B4.

Почему так по числам этого файла: дефекты, из-за которых стенд нельзя показывать, закрываются 12–21 днём задач. Перенос стоит 41–78 дней и эти дефекты сам не закрывает. CSRF, cookie и проверка «маршрут без роли не стартует» уже есть. Готовая админка Django не заменяет T-003, пока она обязана жить под `require_role`.

До записи выбора не открывать T-002: задача правит `auth.py` и добавляет миграцию. Два дня до 06.11 меньше, чем выбросить эти 3–5 дней при решении «переходим». T-004 (новые шаблоны) тоже лучше после записи: при Django шаблоны другие. PR #125 не трогать этим решением.

Если выбор будет «переходим», в ту же запись стоит явно указать объём: узкий каркас (21–37, SQL остаётся, причина ORM не выполнена) или полный (41–78). Иначе исполнитель выберет объём сам.
