## HQ-041 S6 — блокирующий шлюз «Периметр входа» (Д-59 / D-013), ветка `claude/issue-37-20261026-0730` → master (Claude, 26.10)
**Сделано**
- `s6_perimeter/engine.py` — чистая логика. Поля: юрлицо, форма сделки, чек, ковенанты, транши; у каждого `{value, evidence}`. Нет данных / нет доказательства / значение вне политики → `NEEDS_EVIDENCE`; иначе `PASS`. `admit()` — единственная проверка допуска: результат пересчитывается из входных данных (подмена `result` в хранилище не помогает).
- `s6_perimeter/perimeter_policy.yaml` — все пороги и списки (образец — `s2_mandate/investment_policy.yaml`, путь можно переопределить `S6_POLICY_PATH`). Каждый раздел `status: hypothesis`: в каноне Д-59 / D-013 мне доступен только состав полей и правило NEEDS_EVIDENCE, значений нет.
- `s6_perimeter/blueprint.py` — `/s6/gates` (POST создать), `/s6/gates/<id>` (GET), `/forward-to-s2` (POST), `/release` (POST). Роли только через `auth.require_role`: создание/просмотр/передача — owner и fund_staff, release — только owner; investor → 403, без входа → 401. Release требует `reason`, пишет email owner и хеш данных; другие данные (новый шлюз) решение не наследуют. Автоматического снятия нет.
- `forward_to_s2()` — единственный путь S6 → S2 (HTTP и прямой вызов проходят `admit()`), создаёт запись S2 той же формы, что `/s2/checks`, через публичные `validate_input/evaluate` S2.
- `s6_perimeter/s5_link.py` — `entry_passport()` собирает `portfolio_update.EntryPassport` из пройденного периметра. S5 и S2 не изменены.
- `app.py` — только регистрация blueprint; `docs/ACCESS_MATRIX.md` — строки `/s6/*`.

**Не проверено / решения для MOS Tech и Бориса**
1. **Прямой `POST /s2/checks` (admin-токен) по-прежнему принимает заявку без S6.** Закрыть его значит менять поведение S2, что запрещено п. 5. Блокировка действует для пути через S6; чтобы шлюз стал единственным входом в S2, нужно отдельное решение (напр. S2 требует `s6_gate`).
2. Все значения политики — гипотезы (допустимые формы ООО/АО, виды инструментов, чек 6–10 млн ₽ как в S2, типы ковенантов, 1–5 траншей, сумма траншей = чек). Нужна сверка с Д-59 / D-013 — самих документов у исполнителя нет.
3. Значение вне политики (не только пустое) тоже даёт `NEEDS_EVIDENCE` — отдельного статуса «отказ» в задаче нет.
4. `evidence` — только непустая ссылка-строка; существование и содержание документа не проверяются.
5. Записи шлюза лежат в таблице заявок S1 (`data.s6`), как у S2/S3, и видны в `/s1/jobs`.
6. `sector` и `innovative` для S2 не входят в периметр — передаются в теле `forward-to-s2`.
