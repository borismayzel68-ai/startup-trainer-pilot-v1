# Проверка стенда 30.10 · отзыв согласия ПДн только своего (ветка `fix/consent-revoke-own-only`)

- Найдено независимым ревью защиты 30.10 и подтверждено тестом: `POST /consent/revoke` открыт без входа; любой посетитель
  берёт CSRF-токен со своей страницы `/consent` и отзывает согласие **любого** email. Последствия: в журнале 152-ФЗ запись
  об отзыве, которого человек не делал; вход жертвы блокируется до нового согласия.
- Исправлено: вошедший пользователь отзывает все строки своего email; без входа — только строки, отмеченные в этой же
  сессии браузера (ID строк, до 10, в подписанной cookie). Нет таких строк — 403 `consent_not_yours`.
- Ревью 30.10 (второй агент) нашёл обход первой версии: посетитель сам отмечал согласие на чужой email и отзывал все строки.
  Теперь отзываются только ID своей сессии (`PdnConsentStore.revoke_ids`), исходное согласие человека остаётся. Проверено и на Postgres 16.
- Остаток (решает юрист): человек без входа и в другом браузере отзывает согласие письмом на контактный адрес из текста.
- Тесты: `tests/test_pdn_consent.py::test_revoke_foreign_email_forbidden`, `::test_revoke_after_own_submit_for_victim_email_keeps_victim_consent`. ACCESS_MATRIX.md обновлён.
