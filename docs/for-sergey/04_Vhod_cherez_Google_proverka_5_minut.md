# Вход через Google не работает: проверка за 5 минут

`<ДОМЕН>` — адрес стенда без `https://`. Ключи, секреты и пароли в чат и в issue не писать.

## Проверка по порядку
1. **Почта в списке допущенных.** В `.env.staging` переменная `AUTH_ALLOWLIST` содержит почту тестировщика в формате `email:роль` (через запятую), например `tester@example.test:investor`. Это самая частая причина: вход через Google проходит, а стенд отказывает. Браузер теперь покажет страницу «Доступ по приглашению» с почтой, под которой вы вошли; в журнале будет строка `auth: not_in_allowlist s***@домен`. После правки `.env.staging` перезапустите приложение.
2. **Почта в «Тестовых пользователях» Google.** Google Cloud → «OAuth consent screen» (или «Google Auth Platform» → «Audience»). Если режим «Testing», почта должна быть в списке «Test users».
3. **HTTPS и здоровье.** Откройте `https://<ДОМЕН>/health`: ответ `ok`, в браузере замочек.
4. **Адрес возврата.** В Google и в `AUTH_REDIRECT_URI` одна и та же строка: `https://<ДОМЕН>/auth/callback` (без `/` в конце).

## Какая ошибка что значит
| Что видно | Причина |
|---|---|
| Страница Google: `redirect_uri_mismatch` | Адрес в Google ≠ `AUTH_REDIRECT_URI`. Страница ошибки показывает запрошенный адрес — скопируйте его в Google. |
| Google: `access_denied` / «приложение не прошло проверку» | Режим «Testing», а почта не в тестовых пользователях (пункт 2). |
| Google: `invalid_client` / `401` | Опечатка в `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` или остался старый секрет после перевыпуска. |
| JSON `oauth_not_configured` (503) | Не заданы ID или секрет в `.env.staging`. |
| JSON `oauth_failed` (400/502) | Не совпал state: нет cookie, обычно из-за отсутствия HTTPS. Либо сервер не достучался до Google. Подробности — в журнале приложения. |
| Страница «Доступ по приглашению» (403; для API — JSON `not_in_allowlist`) | Почты нет в `AUTH_ALLOWLIST` (пункт 1). |
| JSON `consent_required` / `consent_email_mismatch` (403) | Согласие на `/consent` не отмечено или отмечено другой почтой, чем вход через Google. |
| Вход «не держится», возврат на логин | Нет HTTPS или `TRUSTED_PROXY_COUNT` не `1`. |
| Контейнер не стартует | `staging_guard` не нашёл одну из обязательных переменных (список — в `03_Stend_chto_ustanovit_i_kak.md`, раздел 5). |

## Что прислать, если не заработало
(1) текст или скриншот ошибки без ключей; (2) `docker compose logs --tail 30 app`; (3) «совпадает / не совпадает» адрес возврата в Google с запрошенным.

Перевыпуск секрета клиента (он был виден в превью Telegram) — решение Бориса, Q-B3.
