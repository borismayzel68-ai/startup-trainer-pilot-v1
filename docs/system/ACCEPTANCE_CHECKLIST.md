# Чек-лист приёмки

Заполняется в каждом PR (шаблон: `.github/pull_request_template.md`).

1. **Сторона:** площадка (BrainBox, Rounds) / стартап / инвестор / фонд Artgen / портфельная компания.
2. **Снятая рутина / боль / нехватка экспертизы:** что именно пользователь больше не делает сам. Нет ответа — функция не строится (Д-56).
3. **Ценность для покупателя актива:** как изменение повышает ценность MOS для будущего покупателя (данные, пары прогноз↔исход, удержание).
4. **Уровень доказательности:** E0–E4 для каждого claim; golden-снимки меняются только при понижении статуса claims.
5. **Ограничения:** синтетические данные; ничего наружу (письма/Telegram — только Борис); pytest зелёный, лог в PR.
6. **Решения 12.10:** см. LIVING_SPEC.md §5.
7. **Дашборд кабинета:** на дашборде роли есть главный вопрос, красные флаги и следующий шаг (LIVING_SPEC.md, «Дашборд кабинета»); инвестору — без инвестсовета; цвета фонда/портфеля — по порогам runway/burn.
8. **Доходность (ILPA/IPEV):** 3–5 KPI сверху, тренд по кварталам, флаги, детализация; у каждой цифры дата, источник, E0–E4; бумажная и реализованная прибыль раздельно; проценты и конвертация займов раздельно; расчёт из условий входа, отчётов и узла «Исход сделки» без нового ручного ввода; в дашборде фонда только вложено по сделкам, оценка с датой и E-уровнем, доход по займам, MOIC/IRR по сделке; LP-метрики (TVPI/DPI/RVPI, management fee, carry, NAV для LP) НЕ включены до появления LP (процесс 20).
