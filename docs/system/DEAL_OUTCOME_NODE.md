# Узел «Исход сделки»

Назначение: копить пары **прогноз ↔ исход**, чтобы калибровать скоринг и подтверждать ценность данных для покупателя актива.

Поля (черновик, синтетика):
- `deal_id` (псевдоним), `forecast_ts`, `forecast` (сырой балл 0–100, цвет, уровни E0–E4 claims, версия методики);
- `outcome_ts`, `outcome` (инвестировано / отказ / в процессе / иное), `outcome_source`.

Поля для доходности (дополнение 13.10, черновик): `invested_amount`, `entry_terms` (в т.ч. тип инструмента; для конвертируемого займа — ставка и условия конвертации), `payouts` (дата, сумма), `valuation` (дата, значение, источник, E0–E4; ежеквартально), `realized` / `unrealized` — раздельно. Из них считаются MOIC, IRR, DPI, RVPI, TVPI (LIVING_SPEC.md, «Доходность в дашбордах»).

Правила: пары неизменяемы (исход добавляется отдельной записью); статус оплаты в узел не пишется; сырой балл только копится и не показывается пользователю; в первом релизе узел не влияет на цвета.

Открыто: схема хранения и владелец — до 19.10.
