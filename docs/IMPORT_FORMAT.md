# IMPORT_FORMAT — CSV-импорт dealflow (MOS-3)

`python scripts/import_dealflow.py --migration-plan a.csv --core-dashboard b.csv --books c.csv [--apply] [--report путь] [--format md|json]`

Реальные выгрузки кладутся в `imports/` (игнорируются git) и **никогда не коммитятся**. В репо — только синтетика в `tests/fixtures/import/`.
`--report` принимает путь только вне репозитория. Для `--apply` нужен `SESSION_DATABASE_URL` (или `--db-url`) и применённые миграции (`003_dealflow.sql`).

## Колонки (UTF-8, заголовок обязателен, регистр не важен)

| Источник | Колонка (синонимы) | Обязательна |
|---|---|---|
| все | `VC ID` (`vc_id`, `id`) | да (строки без ID — в отчёт) |
| все | `Название` (`name`) | да |
| все | `Ссылка` (`link`, `url`) | нет |
| план миграции | `Зона` (`zone`) | да |
| план миграции | `Этап` (`stage`, `status`) | нет |
| CORE-дашборд | `SCREENING` | да |
| CORE-дашборд | `INVESTMENT_VIEW`, `PROCESS_ACTION` | нет |
| книги v4.0 | — (статуса нет) | — |

Названия колонок реальных выгрузок мне не передали: набор выше — допущение, при расхождении поправить `_COLUMNS` в `dealflow/importer.py`.
Статус считается по `docs/STATUS_MAPPING.md` (`map_zone`, `map_core`). Книги статус не дают.

## Ссылки Drive
Из ссылки извлекается только id файла/папки (`/file/d/<id>`, `/document|spreadsheets|presentation/d/<id>`, `/folders/<id>`, `?id=<id>`); сама ссылка не хранится. Результат — строка в `documents` (`kind` = `drive_file` | `drive_folder`, `title` = название). Нераспознанная ссылка — в отчёт.

## Отчёт
Строк по источникам; контрольные ID (VC-028, 085, 103, 104, 170, 176, 182); **дубли** (ID повторяется внутри одного источника); **конфликты** (разные названия или статусы на один ID между строками и источниками); ID, требующие ручной проверки (статус не распознан); ID без источника статуса (только книги); строки без ID; неизвестные зоны; нераспознанные ссылки.

## --apply
Одна транзакция. Пишутся только «чистые» ID: upsert `startups` (`source='import'`), смена статуса через `change_status` с `reason='import'`, `documents` без дублей. Дубли, конфликты, ID на проверке и без статуса **не записываются** — остаются в отчёте до ручного решения. ID с нераспознанной ссылкой на документ тоже блокируется (в отчёте — «Нераспознанные ссылки»). Если стартап уже есть в БД и создан не импортом (`source` ≠ `import`), а статус в CSV другой — статус не меняется, строка выводится в отчёт apply как КОНФЛИКТ. Недопустимый переход статуса стартапа, созданного импортом, пропускается и попадает в отчёт. CSV читается как UTF-8 с BOM или без, LF или CRLF; файл только с заголовком даёт пустой отчёт. Повторный запуск ничего не меняет.
