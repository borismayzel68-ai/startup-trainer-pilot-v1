## 1. Минимальный состав brief

Каждое поле берётся из данных S1. Ниже указано, откуда именно, и что делаем, если поля нет. Статусы данных (HQ-035, ветка fix/hq-035-fact-ceiling): FACT «факт» (E3/E4 + подпись owner/analyst, Р-5, Д-41), FACT_CANDIDATE «заявление с документом» (E3/E4 без подписи), FOUNDER_CLAIM «заявление», UNKNOWN «нет данных», CONFLICT «противоречие». Без подписи человека FACT не ставится. Уровни доказательства E0–E3 взяты из журнала S1.

Запрещено в brief (БП-02 §8): слово INVEST и язык term sheet (лист условий сделки). **Оценка компании (valuation) — по Д-52 (канон v1.8.1, главенствует):** разрешён только диапазон по аналогам с методом, списком аналогов и пометкой «ИИ-оценка диапазоном, не цена сделки и не рекомендация»; точечная цифра и вердикт оценки моделью запрещены; цифру ставит человек. Метки PASS/HOLD/NEXT не показываются (ОК-1). На каждом brief: бейдж «Разбор рисков MOS · дата · версия» (90 дней, согласие стартапа, публикация через G-4) и пометка «ИИ-оценка, не инвестиционная рекомендация».

**Как формируется вердикт.** Порядок: сначала Марк и Анна пишут позиции независимо, каждый только по пунктам 3 и 4. Потом правило сводит их позиции. Потом человек подписывает. Утверждённых критериев S2 на Drive нет (задача MET-02, «готовность — НЕ ПОДТВЕРЖДЕНО»). Поэтому ниже **предложение**, которое должен утвердить MET-02 / PM:
- **отказать** (= pass-on-process по БП-02: прекратить процесс, это не решение фонда): мандат no-go или сделка вне LS; либо kill gate Анны подтверждён FACT, а у Марка нет FACT, который его снимает.
- **углублять** (deepen): мандат пройден; есть de-risk milestone (п. 7); главный риск Анны можно проверить конкретным документом или тестом; ни один kill gate не подтверждён FACT.
- **наблюдать** (watch): мандат пройден, но главный риск сейчас проверить нечем (UNKNOWN, следующая веха позже) или de-risk milestone не сформулирован.

**Как вердикт различается для Марка и Анны.** У каждой роли нет своего вердикта, у неё только своя позиция. Марк тянет к «углублять», Анна к «отказать». Если по главному риску позиции расходятся, это записывается как CONFLICT. Такой случай не может дать «углублять», пока противоречие не закрыто документом. Итоговый вердикт один и принадлежит человеку (Human Gate). Отдельно проверяем вопрос из декомпозиции: «дают ли две ИИ-роли реальный спор или одинаковые выводы с разной окраской».

## 2. Критерий приёмки

**Один brief: PASS, только если выполнены все проверки.**
1. Есть поля 1–10, ни одно не пустое без пометки «нет данных».
2. У каждого FACT есть источник и дата. Ни один CLAIM не повышен до FACT.
3. Каждый пункт Марка и Анны ссылается на конкретную строку пунктов 3–4. Если позиции Марка и Анны совпадают по смыслу, это FAIL.
4. Вердикт следует из правила раздела 1. Ревьюер, который не писал brief, выбирает тот же вердикт **по одному brief**, без устных пояснений (DoD БП-02 §12).
5. Нет слова INVEST и языка term sheet. Оценка — только диапазон по Д-52 с методом, аналогами и пометкой; ни одной точечной цифры оценки. Нет цифр без источника.
6. STOP-кейсы (вне LS, no-go, пустой пакет) остановлены и не получили вердикт «углублять».
7. Подпись человека есть. Без неё brief никуда не ушёл.
Любая невыполненная проверка = FAIL.

**Серия 26–30.10: 10–15 реальных LS-кейсов.**
- Серия принята, если **не меньше 10 кейсов** получили PASS по всем семи проверкам. Счёт ведётся как «X из N», без процентов.
- **Ни одного** FAIL по проверкам 2 и 5 (выдуманные данные, повышение доказательства). Один такой случай = серия не принята до исправления и повторного прогона этого кейса.
- В серии есть хотя бы по одному кейсу на каждый вердикт и хотя бы один STOP-кейс.
- Каждый кейс прошёл через тот же интерфейс, что и при показе 5.11, без ручных «костылей». Если для этого нужна правка кода: **нужен HQ-номер от MOS PM**.

**Кто принимает и по какой цепочке:**
`Executor (исполнитель прогона) → артефакт (brief md+json и запись в LEDGER) → GPT Verdict (независимая проверка по 7 пунктам) → HQ_Trainer evidence (brief, вердикт и протокол серии в папке) → PM GO (MOS PM закрывает серию)`.
Проверку 4 делает человек-ревьюер (аналитик фонда; имя **НЕ ПОДТВЕРЖДЕНО**). Executor PASS себе не ставит.

**Главный риск.** Brief строится из данных S1, но в LEDGER сейчас 1 реальный кейс (VC-179, без `raw_json_url` и без строк Evidence Delta) и 4 синтетических (VC-995…998). Строки Evidence Delta есть только у синтетического VC-995. Чтобы провести серию 26–30.10, S1 сначала должен прогнать 10–15 реальных LS-кейсов и записать Evidence Delta. До freeze 25.10 это зависимость номер один.
